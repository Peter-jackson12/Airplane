## 3. 재측정이 기존 서술에 대해 말하는 것

판정 기준은 AUDIT.md §3-10 을 따른다 — **Macro F1 / AUC 차이가 0.002 이하면 
실질 개선으로 인정하지 않는다.** early stopping 과 임계값 선택에서 오는 잔여 
편향이 그 크기이기 때문이다.

> 기존 최고 기록(0.4587, 누수 포함 Phase 5)보다 낮다(§3-7 참조).

### 3-1. Phase 5 는 여전히 Phase 6 보다 우수한가?

* 정직한 Phase 5 AUC `0.6222` vs Phase 6(수정) AUC `0.6332` → 차이 `-0.0110`
* 정직한 Phase 5 F1 `0.5630` vs Phase 6(수정) F1 `0.5696` → 차이 `-0.0066`

**판정: 뒤집혔다.** 누수 제거 후 Phase 6 이 우세하다. 
기존 서술은 수정되어야 한다.

### 3-2. Phase 5 누수의 실측 크기

| 지표 | 누수 재현 | 정직 | 차이(= 누수 크기) | AUDIT §3-6 추정 |
| :--- | ---: | ---: | ---: | :--- |
| ROC-AUC | 0.6379 | 0.6222 | **+0.0157** | +0.002 ~ +0.008 |
| Macro F1 | 0.5735 | 0.5630 | **+0.0105** | +0.002 ~ +0.006 |

**추정 상한을 넘었다.** 누수가 예상보다 크다. §2.1-C 의 억제 요인 분석을 재검토해야 한다.

fold 별 pseudo 선별 건수(정직): 97,946, 97,764, 131,135, 106,693, 114,292 — 
최소 97,764 / 최대 131,135, 편차 33,371건. 
fold 마다 teacher 가 다르므로 기존 기록의 **89,438건 고정이 성립하지 않는다.**

### 3-3. Phase 3→4 의 "AUC 반등"은 재현되는가?

* Phase 3 AUC `0.6424` → Phase 4 AUC `0.6305` → 차이 `-0.0119`
* 구프로토콜 기록: 0.6043 → 0.6107 (차이 +0.0064)

**판정: 재현되지 않는다. 부호가 뒤집혔다.** 통일 프로토콜에서는 원본 범주를 
복원한 Phase 4 가 TE 단독 치환인 Phase 3 보다 **오히려 낮다**. 
구프로토콜의 "AUC 반등"은 프로토콜 요인(임계값 그리드, TE 방식)이 만든 
허상이었을 가능성이 크다.

이는 PLAN.md §3-A 항목 2("하이브리드 카테고리 보존")의 근거를 직접 흔든다. 
해당 도메인 규칙은 재검증 전까지 보류해야 한다.

### 3-4. TE 내부 K-fold 도입의 단독 효과

| 지표 | inner_splits=0 (기존 방식) | inner_splits=5 (신) | 차이 |
| :--- | ---: | ---: | ---: |
| ROC-AUC | 0.6071 | 0.6305 | +0.0233 |
| Macro F1 | 0.5550 | 0.5704 | +0.0154 |

이 차이만큼은 **"프로토콜 통일"이 아니라 "TE 방식 변경"의 효과**다. 
§2 대조표의 신구 차이를 해석할 때 이 몫을 먼저 덜어내야 한다.

### 3-5. Traffic 결측 버킷 수정(AUDIT §3-8)의 순효과

| 지표 | 레거시(-1 뭉침) | 수정(결측 제외 + 플래그) | 차이 |
| :--- | ---: | ---: | ---: |
| ROC-AUC | 0.6343 | 0.6332 | -0.0011 |
| Macro F1 | 0.5724 | 0.5696 | -0.0028 |

**판정: 성능 차이는 유의하지 않다.** 다만 수정본은 `Origin_Traffic` 이 
혼잡도만 측정하고 결측 여부는 별도 플래그로 분리되므로, **피처 의미가 
해석 가능해진다**는 이점은 성능과 무관하게 유효하다.

### 3-6. 0.002 규칙을 적용했을 때 실제로 남는 Phase 전이

| 전이 | ΔAUC | ΔMacro F1 | 판정 |

### 3-7. `scale_pos_weight` 가 early stopping 을 조기 종료시킨다 (진단)

LightGBM 은 `scale_pos_weight` 를 **평가셋에도 적용**한다. 그래서 early 
stopping 이 보는 지표가 가중 버전이 되어 매우 이른 회차에 멈춘다. 
`metric` 을 `auc` 로 바꿔도 동일하게 재현되므로 원인은 metric 이 아니라 
가중치 자체다. 기존 7개 스크립트가 전부 이 설정을 쓰고 있었다.

| 항목 | spw 적용 (Phase 4 기준 설정) | spw 미적용 |
| :--- | ---: | ---: |
| fold별 best_iteration | `[2, 2, 2, 2, 2]` | `[567, 54, 502, 562, 64]` |
| LogLoss | 0.4635 | **0.4553** |
| ROC-AUC | **0.6305** | 0.6252 |

읽어야 할 지점은 **2-트리 모델의 AUC 가 500-트리 모델보다 높다**는 것이다. 
추가 부스팅이 랭킹 품질을 떨어뜨린다 — 이 데이터의 신호가 실제로 얕다는 
뜻이며 프로토콜 결함이 아니다. 다만 **LogLoss 는 spw 를 끌 때 뚜렷하게 
낮아진다** (0.4635 → 0.4553). 기존 프로젝트가 "LogLoss 0.45대 진입"을 
성과로 기록해 온 만큼, 그 값이 누수도 준지도 학습도 없이 **하이퍼파라미터 
한 줄로** 얻어진다는 사실은 해당 서사를 다시 보게 만든다.

> 본 재측정의 주 비교표(§2)는 지시대로 Phase 4 설정(spw 적용)을 전 Phase 
> 고정으로 유지했다. 위 행은 진단용이며 Phase 순위 비교에는 넣지 않는다.

## 4. 한계

* 본 재측정은 **단일 시드(42)** 의 5-Fold 1회 실행이다. fold 분할 자체의 
변동을 반영하지 않으므로, 0.002 근처의 차이는 시드를 바꾸면 순위가 뒤집힐 수 
있다. 확정하려면 시드를 바꿔 여러 번 반복해야 한다.
* 하이퍼파라미터를 Phase 4 설정으로 고정했으므로, 각 Phase 가 **자기 피처셋에 
최적인 설정**에서 얼마나 나올 수 있는지는 측정하지 않았다. 이는 의도된 것이다 
— 혼입 요인을 줄이는 대신 각 Phase 의 상한을 포기했다.
* `naive_macro_f1` 은 기존 스크립트 방식의 재현일 뿐이며 성능 수치가 아니다.
