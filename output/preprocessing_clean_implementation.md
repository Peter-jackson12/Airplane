# 전처리 개선 구현 및 전수 검증

2026-09-16. 날씨 병합은 보류하고 원본 데이터 안에서 해결할 수 있는 세 항목을 수정했다.
기존 실험 정의는 보존하고 `P4_clean`, `P6_clean`을 `rerun_all_phases.py`에 추가했다.
이 두 조건은 개선 묶음이며 개별 변경의 성능 기여를 분리한 실험은 아니다.

## 변경한 규칙

| 항목 | 기존 | 개선 | 남은 한계 |
|---|---|---|---|
| 항공사/코드 대치 | 해당 코드의 첫 관측값 | 관측 대응이 하나인 키만 대치 | 관측상 유일함이 원천 정답을 보장하지 않음 |
| 시간차 | Estimated_Duration | Local_Time_Gap_Minutes라는 명시적 이름 | 시간대 미보정. 실제 비행시간 아님 |
| 거리/시간차 | 분모에 1e-5 더해 나눔 | 유한한 양수 분모만 나눔, 그 외 NaN+플래그 | Distance_Per_Local_Minute는 물리적 속도가 아님 |
| 시각 미상 | Phase 6에서 Sin/Cos 계산 시 정오 대치 | NaN+Dep_Hour_Missing | 복원된 시각도 실측 시각은 아님 |
| 복원 이력 | 복원 후 원래 결측 여부 소실 | 출발·도착 원래 결측 및 시간차 원래 결측 플래그 | Route/전역 중앙값의 배포 가용성은 별도 검증 |

0분 시간차는 현지 시계상 가능한 값이므로 행이나 시간차 자체를 삭제하지 않았다.
비율 계산에서만 제외했다. 시각·거리의 극단값을 임의 상한으로 자르지 않았다.
공항→State에도 동일한 유일 대응 규칙을 적용한다. 양방향 대치는 대치 이전 관측 쌍에서만 사전을 만든다.

## 실제 100만 행 전후 결과

| 검사 | 기존 | 개선 |
|---|---:|---:|
| 원본 Airline 결측 | 108,920 | 같은 원본 |
| 대치 후 Airline 결측 | 11,864 | 78,312 |
| 채운 Airline | 97,056 | 30,608 |
| 원본 순서 반전 시 대치값 변화 | 이전 전수 진단 27,536행 | 이번 전수 검사 0행 |
| 0분 시간차 행 | 370 | 370 (행 보존) |
| 거리/시간차 비율 최댓값 | 75,800,000 | 581 |
| Phase 6 시각 미상 Sin/Cos | 정오 값으로 표현 | 11,688행 NaN |

모호한 대치 **66,448건**을 하지 않게 됐다. 결측이 늘어난 것은 실패가 아니라 불확실성을 보존한 결과다.
관측된 항공사명은 변경하지 않았으며 원본 전체 DataFrame의 순서를 반전해도 개선 대치 결과가 동일함을 확인했다.
비율 최댓값 581도 실제 속도로 해석하지 않는다. 이번 수정은 0분 분모의 폭증을 없앤 것이며
모든 시간/거리 해석 문제가 해결됐다는 의미는 아니다.

| 조건 | 라벨 / 미라벨 행 | TE 전 피처 수 | 출발 Sin 결측 | 비율 결측 | 비율 최댓값 |
|---|---|---:|---:|---:|---:|
| P4 | 255,001 / 744,999 | 15 | 109,019 | 206,371 | 75,800,000 |
| P4_clean | 255,001 / 744,999 | 21 | 109,019 | 206,741 | 581 |
| P6_fixed | 255,001 / 744,999 | 19 | 0 | 0 | 75,800,000 |
| P6_clean | 255,001 / 744,999 | 25 | 11,688 | 370 | 581 |

모든 조건에서 행수·양성 45,000건을 보존하고 수치 피처에 무한대가 없음을 검사했다.
P6의 원래 시간차 결측은 기존 Route/전역 중앙값으로 복원하므로 비율 결측은 0분인 370행이다.
복원되지 않은 시각과 원래 결측이었다가 복원된 시각을 별도 플래그로 구분한다.

## 코드와 호환성

- `src/features.py::impute_cross(..., conflict="unique")` 추가. 기본 `first`는 과거 재현용 유지.
- `build_cyclic_features(..., add_missing_flag=True)` 추가. 기존 호출 기본값 유지.
- `build_speed_features(..., safe=True)` 신설. 개선 모드에서 명확한 이름과 결측 처리를 적용.
- `rerun_all_phases.py::PhaseSpec.safe_preprocessing` 추가. 캐시 키와 실험 메타데이터에 반영.
- `P4_clean`, `P6_clean`은 기존 P4/P6_fixed를 기반으로 만든 별도 선택 조건.
  기존 P4/P6 정의와 원본 run_*.py의 동작은 보존했다.
  Phase 목록에 추가되어 `--phases` 미지정 전체 실행 시에는 신규 조건도 포함된다.

기존 노트북·결정표는 수정 전 진단 기록이다. 현재 개선 경로 설명은 이 보고서를 우선 참고한다.
PLAN/README/AUDIT 및 기존 진단 기록을 덮어쓰지 않았다. 커밋/푸시는 실행하지 않았다.
